# Release CI reds (v0.57.0): clear the pre-existing deterministic reds + load-timeout flakiness that forced the one-time --skip-ci waiver

```routing
lane: ci
tracker: pub
```

Process cause: none

## Provenance
- v0.57.0 was cut and published 2026-11-14 with a one-time `--skip-ci` waiver
  (operator-authorized) because the ci-fast gate was red on the prior tip
  `17892788c96` **before** the release commit `a0ced0c6dee`. These reds are
  pre-existing whole-tree invariant debt + host-load timeouts, NOT a regression
  from the release. 0 real data races; 9 timeout/deadline lines on the prior tip.
- This ticket is the root-cause follow-up the waiver was deferred to. Clearing
  these makes the next `fak release ship` green without a waiver.

## Work items (in order)

### A. Deterministic reds (whole-tree invariant debt)

1. **`TestCheckedInPageIsFresh` (cmd/verbsdoc)** — stale `docs/generated/verb-surface.md`.
   Root-cause fix: regenerate the checked-in page and commit it.
   ```
   go run ./cmd/verbsdoc -write
   go test ./cmd/verbsdoc -run TestCheckedInPageIsFresh -count=1
   ```
   Better tooling: the verbsdoc page must be regenerated by the same verb-surface
   change that makes it stale (pre-commit or a `fak sweep` step), so the checked-in
   page cannot drift from the live surface.

2. **`TestLiveTreeUnderCeiling`** — 4 god files over the line cap:
   - `cmd/fak/guard.go` 1545 > 1506
   - `cmd/fak/serve.go` 2104 > 1584
   - `internal/agent/inkernel_decode.go` 1742 > 1686
   - `internal/agent/inkernel_planner.go` 3388 > 3305
   Root-cause fix: split each god-file into cohesive units with narrow interfaces
   (behavior byte-identical, scoped tests green before/after). One split per commit
   when the construct is large. `cmd/fak/serve.go` and `internal/agent/inkernel_planner.go`
   are the largest and the priority.

3. **`TestTreeEnumExhaustivenessNotGrowing`** — 3 new non-exhaustive switch sites:
   - `internal/compute/cuda_raw_k_offload.go:58`
   - `internal/ctxmmu/compactor_test.go:495`
   - `internal/model/tensor_parallel_sequence.go:180`
   Root-cause fix: add the missing cases (or an explicit `default` with a
   documented reason) so the switch is exhaustive again; the floor test asserts the
   count of non-exhaustive sites does not grow.

4. **`TestRunTreeVerifyMicrobenchmarkMatrixAndOverhead`** — B=1/K=32 simulated
   overhead ratio 1.1766 > 1.15x limit. Root-cause fix: profile the B=1/K=32
   tree-verify path and remove the overhead that pushes the ratio over the 1.15x
   bound (or, if the bound is wrong for this shape, tighten the test's expected
   ratio with a witnessed justification — do NOT raise the limit to make the test
   pass).

### B. Load-timeout flakiness (environmental host load)

5. These reds are host-load timeouts, not logic bugs — they pass on a quiet host
   and time out under fleet load:
   - `TestModelObserveCollectCalibrateAddsHostProbe`
   - `TestPrepushWithoutLazyFetchOption` (+ `/hook` subtest)
   - `TestRunReleaseShipCommandTimeoutReapsGrandchild3103`
   - `TestLinuxSandboxRedThenGreenFixture`
   Better tooling: raise the per-test deadline for these (or gate them behind a
   load-aware skip) so a quiet-host CI run is deterministic. Do NOT delete the
   tests; keep the assertion, only make the timing bound load-tolerant.

## Boundaries
- Public `fak` repo only. Never touch go.mod, go.sum, or fak-private.
- No new scripts (.ps1/.sh/.bat/.cmd). Automation stays native Go.
- Anti-brittle tests: assert closed contracts, never error prose.
- Each red is a separate concern; land one per commit when the change is large
  (god-file splits especially).
