## Captured run

The browser submitted a real turn asking fak to call `Read` on `hello.go`. Stock fak emitted the native progress sequence `turn_started → tool_started → call_adjudicated(ALLOW) → result_admitted → turn_done`, then assistant content and terminal events. The web adapter projected and persisted seven public `fak.harness.run/v1` envelopes:

```text
1 run.started
2 message.started
3 tool.started       Read
4 tool.completed     result admitted by fak
5 message.delta      The Read tool returned ...
6 message.completed
7 run.completed
```

The corresponding remote native-arm receipt reported `tool_calls=1`, `tool_errors=0`, and `engine_calls=1`; the tool ran inside fak's owned loop rather than in the browser client.

## Cursor and process-restart witness

`GET /api/events?run_id=live-1&after=4` returned only sequences 5–7, proving the browser protocol's exclusive cursor. The web process was then stopped and relaunched with the same explicit state file. A fresh browser target loaded `live-1` from disk and rendered the same seven events with `reopened after UI restart · cursor 7`; the screenshot is from this reopened process.

The persisted artifact contains only public semantic envelopes. It excludes tool arguments, tool result bodies, provider objects, credentials, and terminal bytes.

## Honest boundary

This proves a browser-created real fak-owned CUDA tool turn, semantic rendering, exclusive cursor replay, and browser-process restart/reopen. The current demo persists the projection after a completed request; it does not yet detach an in-flight browser request and reconnect that request to stock fak's `Last-Event-ID` progress replay. The UI also has offline scoped-approval, typed failure, and cancellation contract tests, but this run did not exercise a live approval or cancellation. Parent #6790 therefore remains open for the complete coding-harness product surface.
