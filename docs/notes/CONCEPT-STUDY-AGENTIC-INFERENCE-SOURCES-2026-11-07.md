## Corrections to the supplied descriptions

1. **CUDA-Agent releases an example workspace, not its full RL training system.** The pinned tree contains an AXPBY example, its compile/verify/profile loop and a link to an external dataset. Training code and checkpoints are not in this tree. There is no source license at the pin; [issue #11](https://github.com/BytedTsinghua-SIA/CUDA-Agent/issues/11) requests one. Direct source copying is not cleared.
2. **CUDA-Agent's profiler is not an independent correctness authority.** [profiling.py](https://github.com/BytedTsinghua-SIA/CUDA-Agent/blob/473025c8af7878e928525138b5cb327d6bcdf9dd/agent_workdir/utils/profiling.py) sums recorded CUDA durations and can return zero for no recorded work. It neither calls the correctness validator nor fixes the baseline's precision policy. The maintainer [acknowledges one constant-output task](https://github.com/BytedTsinghua-SIA/CUDA-Agent/issues/7#issuecomment-3997870299); commenter precision and speedup tables in #16/#19 are not measurements reproduced here.
3. **AKO4ALL and AKO4X are separate systems.** AKO4ALL supplies a single-run skill and evaluator. AKO4X supplies the cross-round archive and master orchestration. Its [master instructions](https://github.com/TongmingLAIC/AKO4X/blob/ce030ebd855dffb7ba6bdaef7ba7504a92cb9393/master/MASTER.md#L87-L94) explicitly assign proposal gating to agent judgment. Its advisory review hook is nonblocking, not an enforced acceptance gate.
4. **CuTeGen delays profiler feedback rather than necessarily avoiding profiling work.** [codegen.py:178-181,216-218](https://github.com/taratt/cutegen/blob/ea2931ac5398b11acaf5f41598f16fa3768ac469/cutegen/codegen.py#L178-L181) gates prompt inclusion by depth. [validate.py](https://github.com/taratt/cutegen/blob/ea2931ac5398b11acaf5f41598f16fa3768ac469/cutegen/validate.py) calls evaluation, and [evaluate.py:1346,1437-1452](https://github.com/taratt/cutegen/blob/ea2931ac5398b11acaf5f41598f16fa3768ac469/cutegen/evaluate.py#L1437-L1452) profiles after correctness whenever enabled. A profiling-cost reduction requires a separate execution gate and ablation.
5. **The linked index is not the implementation.** Awesome-LLM-Kernel-Agent is a discovery list. The located EvoEngineer repository contains only a README promising a future code release; its paper-author identity is not established. AutoKernel's quick verification skips later stages, so a quick PASS is not full verification.
6. **KernelOPT's optimized result need not mean full-application qualification.** Its measured-shape gate distinguishes failed from skipped; skipped can still permit optimized selection. End-to-end engine validation is optional. Keep per-kernel correctness, measured-shape coverage and whole-engine results separate.
7. **Dynamo KV hints are advisory transfer requests.** [`KvHint`](https://github.com/ai-dynamo/dynamo/blob/403ead2f65ef30941e4a6e848915caf24a64ff69/lib/kv-router/src/kv_hints.rs#L29-L43) defines `kv.fetch@1.0`, explicitly not a pin, with recomputation for missing prefix gaps. This does not establish automatic GPU-to-CPU-to-NVMe demotion on every tool boundary. AgentX G2 tests use simulation rather than physical GPU/model measurements.
8. **LMCache's agentic repository is a demo collection.** Its paper-review/Dify examples and mocked or skipped integration tests do not constitute a rigorous general agentic benchmark. The complete tree has no LICENSE/NOTICE/COPYING file, so direct reuse is not cleared.
9. **KV sharing needs semantic identity.** Mooncake's [`identity.py`](https://github.com/kvcache-ai/Mooncake/blob/0ff71517f0f80a198eebff3009834ed00504b982/mooncake-reshard/python/mooncake/reshard/kv_cache/identity.py#L13-L59) binds namespace, model, weight revision, semantic fingerprint, geometry and full-prefix hash. Network transfer does not make different models, tokenizers or positions compatible.
10. **Cascade attention and asynchronous mask copies are mechanisms, not universal wins.** FlashInfer [runs levels and merges states](https://github.com/flashinfer-ai/flashinfer/blob/9e0e726ffb76aba152e4f1d15564d11d82961349/flashinfer/cascade.py#L562-L569), and warns that merge overhead can lose. SGLang's pinned masks and nonblocking copies alone do not prove separate-stream overlap or zero end-to-end structured-output overhead.

## Bounded kernel candidate decisions

The five inspected kernel-evaluation files were independently byte-matched to public Fak `586496e616034aca63c7d08b92558556ca5844c2`; the links below use that public revision. Rebind call sites before implementation. Read-only capability queries are orientation; source and deterministic witnesses decide parity.

**Caller boundary:** [`computetune/doc.go:12-17`](https://github.com/anthony-chaudhary/fak/blob/586496e616034aca63c7d08b92558556ca5844c2/internal/computetune/doc.go#L12-L17) marks Tune and DispatchMatMul as offline seams. Direct search finds Tune calls in package tests/benchmarks, while `cmd/fak/computetune.go:69` calls the separate storage-compute `Decide` function. K1/K2 harden an offline evaluator; they are not demonstrated live-serving defects or immediate user-visible performance wins. Production adoption needs separately witnessed caller integration.

### K1. Recheck the timed winner after input values change

- **Source mechanism:** AKO4ALL [bench.py:796-870](https://github.com/TongmingLAIC/AKO4ALL/blob/bbd0e1cf1ce2fb19d4322a932680f4c3d175d80e/bench/kernelbench/bench.py#L796-L870) constructs fresh inputs outside timing and rerandomizes the same floating storage after timing. Candidate and reference timing use matched input policy.
- **Fak axis:** [`computetune.Tune`](https://github.com/anthony-chaudhary/fak/blob/586496e616034aca63c7d08b92558556ca5844c2/internal/computetune/tune.go#L213-L277) compares once before warmup, then measures and selects. `Measure` returns duration only. This bounded selection seam is **PARTIAL / OPTIONAL-MODULE**, not a repository-wide correctness-gap claim.
- **First witness:** a stateful mock returns correct output initially and stale/wrong output after timed invocations; it must not become an accepted winner. Trace manifest consumers first to disconfirm the gap if they already perform the required independent recheck. Later use same-storage/new-value hardware trials.
- **Tradeoff and route:** independent behavioral adaptation with attribution review, not a Python sandbox transplant. Preserve numerical floors; evaluator-owned input epochs are a separate small interface change. Extend the existing [CUDA Dojo program #11672](https://github.com/anthony-chaudhary/fak/issues/11672), rather than creating a duplicate broad program.

### K2. Use evaluator-owned value regimes and retain failed trial identity

- **Source mechanism:** KernelBench's [adversarial tests](https://github.com/ScalingIntelligence/KernelBench/blob/423217d9fda91e0c2d67e4a43bf62f96f6d104f1/src/kernelbench/unit_tests/test_eval_adversarial.py#L47-L101) cover result reuse, input modification and stream timing. Verified's [evaluation](https://github.com/facebookresearch/kernel_bench_verified/blob/3fdf6fec7372a4d0cb682635f00e7bdcbc55d50e/src/eval.py#L483-L521) requires all requested hidden configurations and fails if a requested fixture cannot load. Its sampled [fixture](https://github.com/facebookresearch/kernel_bench_verified/blob/3fdf6fec7372a4d0cb682635f00e7bdcbc55d50e/hidden_tests/level1/1_hidden.py#L34-L54) applies floating factors 1, 3, 0.01 and -1; this is value coverage, not arbitrary shape coverage.
- **Fak axis:** the same Tune seam compares one candidate output. **PARTIAL / WATCH** pending an evaluator-owned trial contract. First show a constant-output candidate passes a degenerate single trial but fails the declared alternate regime. Keep operation semantics, precision, shape and seeds explicit.
- **Tradeoff:** extra trials cost time and may be invalid for constrained inputs. Integers/indices and packed layouts need domain-aware generation. AKO4X's [hash-change probe](https://github.com/TongmingLAIC/AKO4X/blob/ce030ebd855dffb7ba6bdaef7ba7504a92cb9393/scripts/benchmark_adapter.py#L310-L398) is only a stale-result heuristic: wrong changing outputs can pass and valid constant operations can fail. It does not replace a reference oracle.

### K3. Reject nonpositive measurement evidence

Fak's Tune path already rejects `duration <= 0`, and [`nativeperf/receipt.go`](https://github.com/anthony-chaudhary/fak/blob/586496e616034aca63c7d08b92558556ca5844c2/internal/nativeperf/receipt.go#L329-L338) requires positive finite throughput/latency fields. **PRESENT / WATCH** at these inspected seams. CUDA-Agent's zero-event report motivates preserving the guard, not a duplicate issue. A positive timer still does not prove correct work; K1/K2 remain separate axes.

### K4. Bind tuned dispatch to exact profile identity

Fak's [`Profile` and manifest lookup](https://github.com/anthony-chaudhary/fak/blob/586496e616034aca63c7d08b92558556ca5844c2/internal/computetune/tune.go#L28-L62) bind M/N/K, dtype, backend/device, software and kernel identity. **PRESENT / WATCH** for this path. Do not infer all live production dispatches are covered. Before importing KernelOPT's selection label, require the named measured-shape and end-to-end witnesses, and treat a skipped gate as unverified.

## Bounded inference candidate decisions

The initial inference comparison used Fak `586496e616034aca63c7d08b92558556ca5844c2`. Existing source studies and live issue readbacks were used for deduplication; an empty local native study search did not mean prior research was absent.

### I1. Reuse compiled schemas across native requests

**PARTIAL / WATCH pending implementation qualification.** The inspected native caller compiles a JSON schema per request, while XGrammar exposes a compiled-grammar cache. Extend the existing compiled-schema reuse design, rather than create another packet. Cache immutable compiled artifacts, not request-local matcher state. Prefer exact schema bytes plus effective compile options within an immutable tokenizer owner; do not introduce unproved canonicalization. Bound retention and keep rejection behavior identical. First prove repeated identical requests share compilation and distinct requests never share mutable matching state. Compile errors, concurrent misses, cancellation and invalidation require explicit tests. This is repeated-work source evidence, not a measured latency improvement.

### I2. Measure complete tool-pause and resume lifecycles

**PARTIAL / RECIPE.** Extend [#8774](https://github.com/anthony-chaudhary/fak/issues/8774) and existing [load-driver work #12510](https://github.com/anthony-chaudhary/fak/issues/12510). SGLang's multi-turn workload includes seeded tool pauses, growing context and complete SSE output validation. Keep one stable request identity across enqueue, prefill/decode, tool pause, cache movement and resumed output. First replay identical seeded workloads and verify complete expected output plus attributable cache/latency events. This should precede claims about idle-KV policies.

### I3. Version and gate KV fetch hints

**PARTIAL / OPTIONAL-MODULE investigation.** Dynamo's `kv.fetch@1.0` is concrete transfer-hint interop, not an eviction or authorization decision. First prove unknown versions, incompatible identities, missing blocks, late transfer and cancellation fall back safely to recomputation. Verify received bytes and scope independently. Add this only for a demonstrated serving topology; Fak retains scheduling and cache authority.

### I4. Preserve provider-specific prompt-cache option semantics

**PARTIAL / OPTIONAL-MODULE on existing work.** Extend [#10385](https://github.com/anthony-chaudhary/fak/issues/10385). Agentic-api offers typed provider capability gates. Test absent fields, unsupported providers, valid breakpoints and stale options without silently coercing meanings. An arbitrary hint accepted by one provider is not portable cache behavior.

### I5. Separate semantic KV identity from physical placement

**PRESENT / WATCH for the inspected semantic mismatch floor.** Mooncake distinguishes semantic cache identity from deployment topology and refuses incompatible descriptors; Fak already has identity guards. A separate optional topology-remapping investigation must test namespace, weights, tokenizer/position semantics, geometry and prefix mismatches plus a valid relocation. Reuse only after exact compatibility. Avoid expanding the contract into arbitrary cross-model or cross-tenant sharing.

### I6. Evaluate multi-level cascade attention on real cohorts

**PARTIAL / WATCH.** FlashInfer's reusable per-level plan and merge path is different from shared allocation or Fak's similarly named V4.1 operation. First compare identical shared-prefix cohorts against independent attention, including zero sharing, unequal lengths, memory peaks and merge overhead. A physical correctness/latency witness is required before a default. More levels can be slower.

### I7. Separate mask staging, overlap and jump-forward claims

**PRESENT / WATCH for tokenizer-bound drafts with target verification.** Pinned host masks, nonblocking device copies and jump-forward each need separate evidence. First verify structured output correctness and trace actual copy/compute overlap with the supported stream lifetime. Existing structured/speculative mechanisms do not prove every donor optimization is wired. Mask staging alone does not establish hidden latency or justify a zero-overhead claim.

### I8. Witness peer-prefetch lifetime and late completion

**PRESENT / WATCH for distinct pending/missing/completed/stale/faulted states.** LMCache peer-prefetch and existing Fak mechanisms need an integration comparison, not a claim that agents instantly inherit context. Test timeout/cancel while a transfer is in flight, lock lifetime, late completion and shared peer registration. Require real transfer and TTFT receipts on the named deployment.

### XGrammar depth pass: ownership and invalidation

Twelve further blob-verified files bring the inference corpus to 57. The old donor pin to this pin changes three CI files only; Fak's compile/mask files are unchanged from the existing design packet. There is no newly shipped cache implementation to rediscover.

- [`thread_safe_cache.h`](https://github.com/mlc-ai/xgrammar/blob/11f65251738b0a1a24618a7bf81505a87fa99ce5/cpp/support/thread_safe_cache.h#L284-L389) coalesces equal-key misses with a shared future. Failed futures can remain cached; there is no cancellation parameter. [Issue #298](https://github.com/mlc-ai/xgrammar/issues/298) remains open. Do not tie a shared producer to the first request's cancellation or advertise a retry policy that has not been specified.
- Clear is eviction, not a generation fence. Finite-budget clear waits for futures under the map lock; unlimited clear drops the map without the same accounting reset. Existing waiters can still receive an in-flight result. Model/tokenizer replacement requires separate ownership or a generation boundary.
- Whole-grammar retention, sharded rule caches, live dynamic objects and peak compilation memory have different budgets. Oversized and concurrent results can exceed a simple retention counter. [PR #1003](https://github.com/mlc-ai/xgrammar/pull/1003) fixed retained allocations in recycled list slots; test actual ownership release, not only counters.
- [PR #943](https://github.com/mlc-ai/xgrammar/pull/943) and [#985](https://github.com/mlc-ai/xgrammar/pull/985) document historical cache-key collisions. Compare cache-disabled masks with cold/warm masks after a contaminating schema, including differing literals, property names, ranges, EOS and options. Preserve exact-key equality if hashing is used.
- `tests/cpp/test_thread_safe_cache.cc` contains commented-out tests only. Active compiler/dynamic/container tests cover selected concurrency, lifetime, clearing and ownership behavior, but none were run here. Fak's existing stream cancellation test is a different boundary, not proof of shared-compile cancellation.
- [PR #1017](https://github.com/mlc-ai/xgrammar/pull/1017) keeps eager compilation as default; dynamic masks may duplicate concurrent computation. JIT compilation is a separate tail-latency tradeoff, not part of the initial whole-schema cache. The returned stable release v0.2.8 predates these later fixes; main-source evidence is not proof of stable-release inclusion.
