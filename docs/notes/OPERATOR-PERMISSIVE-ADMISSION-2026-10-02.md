# Operator permissive workspace admission

Plan: extend the existing gateway lease-admission seam. Scope: gateway verdict projection and `fak serve`/`fak guard` flags, including the stdio gateway. Explicit operator authorization requests a more permissive guard. Default remains strict; omission removes the feature behavior. Witness: `go test ./internal/gateway -run 'TestWorkspaceAdmissionPermissive|TestAdjudicate' -count=1 -timeout=3m`. Coordinator verifies and lands through native commands.

`--workspace-admission-permissive` admits workspace admission `DEFAULT_DENY` failures after kernel permission, including unknown write footprints and unavailable authority. The original ALLOW or TRANSFORM verdict retains its kind and repaired argument contract, identifies `lease-admission-permissive` and records `would_deny`, `would_deny_by`, and `would_deny_claim` in its bounded detail. Known peer `LEASE_HELD` conflicts and kernel policy refusals remain denied. This flag is per process and applies to HTTP and stdio admission.

The environment variable `FAK_WORKSPACE_ADMISSION_PERMISSIVE=1` enables the same mode for installed MCP launchers. Explicit `--workspace-admission-permissive=false` overrides that default. Unset the variable and omit the flag to restore strict admission. Unknown footprints and authority outages can permit writes overlapping an unobserved peer; enable only with that operator-accepted risk. Removing this optional flag and its Config field removes permissive behavior without changing strict admission.

Execution contract: mutating `fak_syscall` and plugin execution retain the atomic guard refusal in strict mode. Permissive execution first checks kernel permission and a fresh peer snapshot using effective transformed arguments, then accepts the missing atomic guard race window. Returned execution verdicts and operation journals record `atomic_workspace_guard=unavailable` and the original atomic `would_deny` cause; snapshot authority failures additionally record `snapshot_would_deny` and `snapshot_would_deny_claim`. A known peer conflict still refuses execution. Unknown or out-of-workspace footprints cannot prove absence of a peer conflict, and permissive admission accepts that risk.

Bound execution reuses Kernel Submit/Reap: inspect the transformed call held by the actual submission before Reap, and discard a refused pending handle through additive `DiscardSubmission`; no second preview fold. Scope adds the concrete kernel pending lifecycle without changing the frozen ABI. Native handlers admit only their single bound Decide ALLOW and check that call before execution. Ensemble members use the same submission guard. Kernel witness: `go test ./internal/kernel -run "TestDiscardSubmission|TestSubmit|TestSyscall" -count=1 -timeout=3m`.

Adjacent canonicalization repair: `adjudicateWorkspacePath` canonicalizes its workspace root before joining or computing relative targets. Raw macOS `/var` temporary roots and `/private/var` target aliases share the same boundary; external symlink targets remain refused. Witness: `go test ./internal/gateway -run TestFakAdjudicateCanonicalizesSymlinkAliasIntoPeerLease -count=1 -timeout=3m`.
