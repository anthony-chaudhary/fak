## Who they built it for, and why it shapes every borrow

Marionette is a Chrome MV3 extension driving **Gemini Nano through Chrome's built-in Prompt API, with a hard 9,216-token context window and zero network egress**. Their user is a privacy-maximalist consumer running an ambient agent over their own browsing session on a weak on-device model. Two consequences run through the whole codebase:

1. **Over-residency is fatal.** Their README (466-473) does the arithmetic in public: 22 tools resident ≈ 2,400 tokens (74% of the window free) versus 9 core tools + playbook one-liners ≈ 850 tokens (91% free). Progressive disclosure is not an optimization for them, it is the only way the agent fits.
2. **The model loops, constantly, and cannot be trusted to recover.** So the *harness* repairs it in-band and keeps going. Their README (line 815) is candid that this is scaffolding — *"as the model gets better at reasoning we can gradually remove these guardrails."*

fak runs frontier models with a vastly larger window, so the naive read is "none of this applies." That read is wrong on the axis that matters: fak's fleet is **autonomous and unattended**, which is exactly where a loop nobody is watching is expensive, and where a *rate* being low does not make the *cost* low. The borrows below survive the difference in model strength because they are about **detection grain and response mode**, not about weak-model babysitting.

## The decisive finding — fak's live loop-breaker cannot see a repeated tool call, by construction

`internal/gateway/messages_resultnotes.go:212-240` — `degenerateStreak` walks back over trailing assistant turns, and its second statement is the premise:

```go
if len(m.ToolCalls) > 0 {
    break // "A turn carrying a tool_use is forward progress and ends the run."
}
```

Repetition is then scored only over `[fak]` echoes and verbatim adjacent prose (`isEcho`/`isRepeat`, lines 231-232). So a model calling the same tool with the same arguments forty times in a row is, by the live steer's own definition, making forward progress on every one of those turns; the streak never starts and `repetitionLoopSteer` (line 291) never fires.

fak already agrees this is a real pathology — it just only notices **after the session ends**. `internal/sessionaudit/behavior.go:60-65, 295-305` computes `RepeatFailures` over `(Tool, Sig, Count)` triples against a `repeatFailureMin` floor. The right detector, in the wrong lens. That is the whole of epic #5904: promote the action-grain signal into the live path, and give it a response that is not "end the turn".

## PRESENT-on-axis — earned dismissals (read fak's code, dropped)

- **Compaction re-prime with hard continuation directives.** Their `formatSummaryMessage()` (`lib/prompts/summarizer-prompts.ts`) appends `[CONTEXT SUMMARIZED …]` plus `- IMMEDIATELY execute the next fillInput call · - DO NOT call think again · - DO NOT ask for confirmation · - DO NOT restart the task from the beginning`, ending with a literal example call. Same axis in fak, and **stronger**: `internal/gateway/compaction_contract.go:13-62` carries `compactionContractInstruction = "continue-do-not-wrap-up"` as a *closed* token, and `compaction_contract_note_test.go:198` asserts the inverse explicitly — *"the note omits the continuation instruction — reporting only the loss is exactly the input that makes a model wrap up early."* A prose directive block versus a tested closed token. PRESENT — drop.
- **Guardrails carry a retirement condition.** Their README (815) says the scaffolding should be removed as models improve — a good discipline, stated as prose in one aside. fak's **"invalidating assumption"** convention is a *required, grep-checked* section in grooming artifacts and contract overlays. Same axis, structurally enforced. PRESENT — drop.
- **Diagrams as committed source, not exported images.** `diagrams/` ships 11 Python Graphviz scripts + `generate_all.sh` + `requirements.txt` alongside the PNGs. fak already commits Mermaid `.mmd` sources beside rendered output, which is *more* reviewable in a diff than Python emitting Graphviz. PRESENT — drop.
- **Unknown-verb "did you mean" suggestion.** Their tool-name misses suggest the near verb; `cmd/fak/main.go:623` and `internal/hooks/commitstamp.go:499` already do this. PRESENT — drop.
- **Retrieval-time span masking / redaction generally.** Present (see #5910's row — the *masking* axis is well covered; only the *ingest-denial* axis is not).

## DIVERGENT and worldview findings — recorded, not filed

- **A single agent loop with no dispatch fence.** Marionette runs one agent in one browser for one human who is watching. Their loop-breaker can afford to be advisory because a human is one keystroke away. fak's constraint is the opposite — unattended fleet workers under a serialized land — which is why fak's existing steer is *terminal* by design, and why #5906 proposes a second mode rather than replacing the first. Not a defect on either side; the tradeoff is attended-vs-unattended, and both answers are right for their user.
- **Instructional-vs-executable content needs a quoting boundary.** `screens/debug-screen.tsx:940-943` notes that *"tool results may contain example tool calls from playbooks that should NOT be parsed"* — their playbook bodies contain literal `<function_call>` examples that the same parser would otherwise execute. fak's skills likewise contain literal command text that a model reads as instruction. This is a **worldview finding**, not a borrow: there is no single axis to witness and no obvious fak seam that is wrong today, and it does not clear the ship-alone bar on its own. Recorded so a later reader can pick it up if fak ever starts round-tripping skill bodies through a tool-result channel.
- **The tool-doc example that teaches the query *domain*.** `lib/tools/findElements.ts:200-203`: `'User: "search for AI podcasts" → findElements with query: "search box" (NOT "ai podcasts")'`. Their playbook one-liners carry **anti-conditions** in the same breath (`lib/playbooks/search.ts:5`: *"ONLY use to open Google.com from scratch. DO NOT use if user is already on a search site"*, closing with *"Do NOT call a tool named 'google-search' - that doesn't exist!"*), and their failure messages name the recovery verb (`content.ts:81`: *"Call findElements or getAccessibilitySnapshot first to get current element indices"*). A coherent house style — every description states what it is *not* for, and every failure states the next call. fak's tool descriptions are already dense and this would be a diffuse cross-cutting edit rather than a shippable leaf; recorded as a style observation, deliberately **not** filed (a "improve all tool descriptions" ticket is exactly the monolith this skill exists to prevent).
- **A privacy claim shipped with its own falsification procedure.** `PRIVACY.md:230-238` tells the reader how to *refute* the zero-egress claim: open DevTools → Network tab → use it normally → observe zero outbound requests. fak already holds this posture elsewhere (witness-or-not-yet), so it is not a borrow — but it is the cleanest example of the discipline in a consumer-facing doc that this pass saw.
