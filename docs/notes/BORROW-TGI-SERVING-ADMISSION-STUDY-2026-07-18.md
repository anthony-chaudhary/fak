# TGI (HuggingFace text-generation-inference) v3 — witnessed borrows for fak

**Study repo:** `huggingface/text-generation-inference` pinned at SHA `b4adbf2`.
**Mined against:** fak `internal/gateway` (admission/serving) + `internal/modelengine`, `internal/abi`, `internal/cachemeta`.
**House fence:** every borrow is witnessed on-axis against real fak code before it is filed or skipped. No borrow is filed that fak already has (dedup first). Citations are `path:line@b4adbf2` for the study side and `path:line` for the fak side.

## Worldview — why most of TGI is coverage, and the overlap is narrow

TGI is a **single-model inference server** whose design pressure is *operational robustness + breadth of model/quant/hardware coverage for the HuggingFace ecosystem*: one binary must load any of ~11 quant formats, run on Ampere/Ada/Hopper/ROCm/IPEX, speak five API envelopes (OpenAI, KServe v2, Vertex, SageMaker, native), and pack thousands of concurrent short completions against one GPU's KV pool without OOM. Its cleverness concentrates in the router↔shard split (Rust front door, Python model shards) and in *auto-sizing itself to whatever GPU it lands on*.

fak is an **agent-governance control plane** (a trust kernel) that adjudicates tool-call / tool-result flows for IFC-taint / quarantine / audit, and serves models as a governed second identity. fak's serving admission stack (`internal/gateway/admission.go`, `batchsched.go`, `preemption.go`, `token_admission.go`, `kv_fleet_routing.go`) is **already built from vLLM V1 / SGLang / Dynamo** (see epic #2236) — it is *not* a blank slate. So the honest result of this study is: fak's scheduler is largely at parity or richer, TGI's broad coverage (quant/spec/MoE/LoRA/multi-envelope) is **DIVERGENT** (fak governs, it does not aim to be a batteries-included HF multi-model host), and the genuine borrows are a small set of **operability refinements to the shipped admission seam** — plus TGI's one structural signature: *measure the machine, then set the budget.*

## Filed issues (3)

Anchored under epic **#2236** (`fak ⊇ best of vLLM+SGLang+Dynamo…`), companion to **#2242** (SLO/goodput P/D planner, typed early-reject admission). Milestone: *Disaggregated serving at throughput parity on one spine*.

- **#5266 — warmup-derived admission `TokenBudget`** (axis 6). Today `readiness_warmup.RunWarmup` (`readiness_warmup.go:134`) already issues a synthetic boot inference but only records boot→first-token latency; `AdmissionPolicy.TokenBudget` is a hardcoded 8192 (`admission.go:94`). Borrow TGI's *measure-then-budget*: have the warmup/serve-stage probe the backend's real token/KV headroom (TGI does this via a max-batch prefill memory probe, `flash_causal_lm.py:1517-1565`, discounted by a `TGI_WIGGLE_ROOM=0.90` safety margin) and set `TokenBudget` from the measured value instead of a static guess. Default-off; static default remains the fallback. Seam: `DefaultAdmissionPolicy` (`admission.go:91`) + `SetAdmissionController` call (`serve.go:401`).
- **#5268 — anti-hog preallocation cap on the admission token charge** (axis 7). `estimateServedAdmissionTokens` (`admission.go:627`) charges the full requested `maxTokens`, so one request asking for a huge `max_tokens` reserves (and can shed) proportionally large budget. Borrow TGI's decoupling (`validation.rs:152-179`): cap the token footprint charged at admission to a preallocation ceiling and re-admit long generations in chunks, so no single request can reserve the whole pool up front. Seam: `admission.go:627` / `SeqRequest.Tokens` `admission.go:115`.
- **#5270 — fail-closed front-door validation of the structured-output contract** (axis 8, validation half only). fak forwards `response_format`/`json_schema` verbatim (`http.go:541`, `wire.go:330`) — a malformed/oversized schema burns an upstream round-trip before the ride engine 400s it. Borrow TGI's *front-door validate-and-reject* (`validation.rs:341-406`: draft-2020-12 meta-validate + mandatory `properties` + size guard → 422) as a cheap fail-closed door check. The *compile-and-cache* half (`logits_process.py:526`) is **DIVERGENT** and explicitly out of scope: fak proxies decoding to vLLM/SGLang, which own the FSM.

## SKIP / DIVERGENT (recorded, not filed) — with reasons

These are TGI's bulk. They are coverage/perf for a single-model HF host and do not match fak's governance worldview, or are GPU-kernel work tracked elsewhere:

- **~11-format quantization dispatch** (`server/.../utils/quantization.py:124`, GPTQ/AWQ/Marlin/fp8/EETQ/exl2/bnb/compressed-tensors) — DIVERGENT: fak serves via llama.cpp/in-kernel + proxied providers; broad on-the-fly dequant is not fak's job. Adjacent fak GPU work: epic #4180 (Blackwell), Track B B-007 (#275 INT4/INT2).
- **Speculative decoding** (Medusa V1/V2 fused head, MLPSpeculator, n-gram/prompt-lookup, `server/.../utils/tokens.py:209-230,365-394`; auto-disabled at batch>128 `layers/medusa.py:102`) — token-level decode kernel work; tracked by Track B B-003 (#284) and epic #4102 (tool-call speculation, a *different* axis). The "disable speculation when compute-bound" heuristic is a nice adaptive knob → note for #284.
- **Fused MoE routing / expert dispatch** (`layers/moe/__init__.py:167-284`) — GPU-kernel; epic #4352 (colibri MoE-SSD), #5243 (net-toks MoE).
- **Multi-LoRA S-LoRA (SGMV/BGMV punica, rank-grouped batching)** (`adapters/lora.py:359-478`) — multi-tenant adapter serving; not a current fak serving identity.
- **CUDA-graph capture / paged-attention V1-vs-V2 / flashinfer plan state** (`flash_causal_lm.py:1369-1505`, `layers/attention/cuda.py:132-185`) — in-kernel decode-latency work; fak's model layer (`internal/model`), GPU-gated (Track B).
- **Five API envelopes over one core** (`router/src/server.rs` route table; SageMaker/Vertex/KServe adapters) — HF deployment breadth; fak exposes OpenAI/Anthropic/MCP already and does not chase SageMaker/Vertex/KServe surfaces.
- **Chat-template execution in Rust via minijinja+pycompat** (`router/src/infer/chat_template.rs:33-133`) — fak proxies templating to the provider; not needed.
- **Radix prefix-cache internals** (compressed radix trie, refcount-gated LRU eviction, partial-block truncation, self-populating-on-free — `backends/v3/src/radix.rs`) — fak has its own KV/prefix cache plane (`cachemeta`, `enginecache`, `vllmcompile`, epics #3320/#3366/#3900/#3983); the *admission-facing* slice of the radix idea (charge only the uncached suffix) is the one borrow worth taking and is **already open as #3893**.

## Reusable seam map (for the next reader)

fak's serving admission/scheduling is concentrated in `internal/gateway/`: `admission.go` (token-budget + max-num-seqs + waiting-queue + aging + trust-deny + `fak_sched_*` metrics), `batchsched.go` (padding-bounded rectangular-prefill batch composition), `preemption.go` (paged-KV swap/recompute), `token_admission.go` (provider TPM/concurrency window), `kv_fleet_routing.go` + `residency_router.go` (prefix-aware cross-instance routing), `readiness_warmup.go` + `readiness_decode.go` (readiness gates), `gateway_admit.go` (the trust-kernel result-side floor).
