# fak v0.56.0: Minor release for compute, model, ggufload, computetrace

This release contains 50 commits: 6 what changed changes, 14 reliability and correctness changes, 30 engineering quality and evidence changes. The sections below are grouped by operator impact, with the complete source history retained for auditability.

## What changed

### Security & Governance
- --dry-admit names what it does not check (load_fit not_run, advisory fit_warnings) and refuses a llama-mtp delegated serve, and bringup keeps device-only and the expert ring until it actually lifts a host refusal.
- Fak serve --execution-policy bringup admits host and offload execution on a bring-up-dedicated Halo, and --dry-admit runs admission alone, so device-only stays policy but never blocks the parity path.

### Serving Engine, Gateway & Kernel Acceleration
- Fak model preflight lists every unread GGUF key, HF-config mismatch, missing/orphan tensor and dtype without a host kernel in one header-only pass.
- IQ4_NL routed experts stay raw-resident on the host GEMV, so Flash-Next's 43 IQ4_NL down_exps layers keep 0.5625 B/weight instead of the Q8 round trip.
- The GGUF loader admits qwen4exp with every key read, 34/34 keys matching the f5d0827 HF config and token ids matching dff6004, so Flash-Next geometry comes from the artifact, not constants.

### Developer Platform, Tooling & Evidence
- Add per-arch llama.cpp stage maps, a public reference-oracle schema and a first-divergence verb, so any bring-up diffs layer by layer against its reference.
