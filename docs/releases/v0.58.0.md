# fak v0.58.0: Minor release for inkling2, metal, run, release

This release carries the Inkling-2-Mini bring-up on CUDA and Apple Silicon Metal, and it
is the first release since v0.56.0 that the Go module proxy can serve. The sections below
are grouped by operator impact; the complete source history is in `git log v0.57.0..v0.58.0`.

## What changed

### Inkling-2-Mini

- Inkling-2-Mini (Apache-2.0, looped MoE) runs fak-native. On one RTX 5080 16 GB with the
  unsloth UD-Q3_K_XL GGUF, the in-process decode bench reaches 119.9 tok/s, at parity with
  the realugbun llama.cpp fork (119.5 tok/s, same card and file). It is parity, not a lead.
- In one window on one RTX 5080 (ABBA x2, same file), fak trunk measured 118.1 tok/s against
  stock llama.cpp at 81.0 tok/s, a ratio of 1.46x. The fork pair above is a separate window.
- All rates are in-process decode benches, not served-endpoint rates.
- Batched prefill is opt-in. It reaches pp512 862.7 tok/s, about a third of llama.cpp's
  2362 tok/s, and the two were measured on different boxes.
- Speculative decode is opt-in (`FAK_INKLING2_SPEC=2` plus `FAK_INKLING2_MTP_DIR`). It
  reached 151.7 tok/s on one node. It stays off by default because the batched check is
  not bit-exact to one-token-at-a-time decode.
- On an M3 Pro, Metal decode runs level with Splash 1.7.2 (40.3 vs 37.5 tok/s; both use
  draft verification). `fak run <path>/Inkling-2-Mini-UD-Q3_K_XL.gguf` picks Metal on Apple
  Silicon automatically.
- Where fak loses today: prefill, and decode at around 2K tokens of context, where fak
  trails the fork (89.0 vs 113.8 tok/s at 1946 tokens of depth).
- The CUDA backend is not in the default binary. It compiles only under `-tags cuda` with
  cgo against nvcc-built kernels: run `make cuda-build`, or `make cuda-build-sm120` for
  RTX 50-series cards, on a host with a CUDA toolkit (see [docs/cuda-dev.md](../cuda-dev.md)).

Every number above has a row in the receipts table of the
[Inkling-2-Mini launch kit](../launch/inkling2-launch-2026-11-24.md).

### Installability

- v0.57.0 was never installable through the Go module proxy. Its module zip was over the
  proxy's 500 MiB cap (`module source tree too large`), so `go install ...@latest` kept
  resolving to v0.56.0. Its release run also failed artifact aggregation, which left the
  GitHub release quarantined as a prerelease, so `install.sh` and Homebrew kept installing
  v0.56.0 too.
- Nested `go.mod` files now keep large data and vendored trees out of the root module, so
  the root module zip fits the proxy cap again.
- The CUDA release binary now loads without a GPU driver, so release aggregation can probe
  the CUDA image on a GPU-less runner.

## Upgrade

No manual migration is required. Install or update with:

```bash
go install github.com/anthony-chaudhary/fak/cmd/fak@latest
```

The CUDA build still comes from a clone: `make cuda-build` or `make cuda-build-sm120`.
