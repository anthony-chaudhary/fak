# fak v0.44.0: easier adoption, safer long-running agents, and stronger proof

**TL;DR:** v0.44.0 makes fak easier to evaluate, safer to run unattended, and harder to fool with an unverified done-claim. It contains **2,249 commits across 5,529 files** since v0.43.0.

Try the tagged release:

```bash
go install github.com/anthony-chaudhary/fak/cmd/fak@v0.44.0
fak agent --offline
```

## Highlights

### Start with a proof, not a promise

- The onboarding path now leads with the no-key offline proof and routes readers to runnable examples.
- Harness release work added clean-room extraction checks and preserved executable permissions in shipped bundles.
- Claude Code, Codex, and MCP integration docs gained clearer entrypoints and verification steps.

### Operate agents with less babysitting

- Dispatch now treats work as leased and observable. It can recover stale ownership, expose live status, and witness worker results before reconciliation.
- Session tooling gained durable continuity, intent capture, compaction diagnostics, and operator-visible context-health signals for long-running work.
- Fleet account routing and failover were tightened so worker capacity, cooldowns, and provider health are checked before work is launched.

### Stronger safety at the tool boundary

- Guard and policy paths gained stricter fail-closed behavior, safer capability routing, durable decision receipts, and broader injection/adjudication coverage.
- Gateway work improved provider compatibility and request validation. It also tightened streaming, routing, and failure classification.
- Destructive and ambiguous operations now carry more explicit refusal, preview, lease, or witness requirements rather than relying on the model to self-police.

### More credible performance and model evidence

- Model and compute work expanded quantization and MoE coverage. CUDA and device-parity tests now exercise more live hardware paths.
- Benchmarking now records richer provenance, comparison baselines, uncertainty, and net-true cost/latency evidence instead of reporting isolated gains.
- Shared helpers removed repeated implementations across packages. This reduces drift in shared parsing and data-handling behavior.

### Release and repository reliability

- Release cutting and tagging gained more idempotency checks. Artifact, container, plugin-version, and stable-promotion paths gained clean-room coverage.
- CI became more deterministic under the shared-trunk workload through bounded fan-out, serialized decisive gates, clearer progress, and stronger architecture checks.
- The public release process now separates human-facing notes from machine provenance and blocks YAML/commit-ledger dumps from being published as release prose.

## Upgrade

No manual migration is required for the standard CLI install. Update with:

```bash
go install github.com/anthony-chaudhary/fak/cmd/fak@v0.44.0
```

If you distribute release assets or containers, verify the checksums attached to this release and keep the binary, plugin, and image on the same tagged version.

## Compatibility notes

- Go 1.26+ remains required for source builds.
- Existing policies and command lines remain valid unless a previously fail-open or ambiguous path is now rejected; those rejections are intentional safety hardening.
- Experimental study packets remain prereleases and are not stable fak versions.
