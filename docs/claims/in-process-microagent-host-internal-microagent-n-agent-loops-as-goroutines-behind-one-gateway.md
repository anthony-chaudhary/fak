# In-process microagent host (`internal/microagent` — N agent loops as goroutines behind ONE gateway)

[← Claims index](../../CLAIMS.md)


- [SIMULATED] `microagent.Host` (#2002, epic #2000 M2) is the in-process alternative to production's ~2 OS processes per agent (a `fak guard` policy proxy wrapping an external CLI) plus one detached process per dispatch lane (`cmd/fak/dispatch_tick.go` spawn path, each with its own hash-chained audit JSONL): one **goroutine** per agent, all sharing ONE in-process gateway seam (`Gateway = agent.Planner`, the seam `internal/gateway.New` builds exactly once), per-agent state as ONE `session.Table` map entry per agent (bounded LRU, limit 8192 — not one process), and ONE `AuditSink` for the whole host. Explicit lifecycle: `Spawn` (bounded queue, loud `ErrQueueFull`) → K-worker `Step` loop → retire (done/cancel/error) → `Reap`, with `Drain` (graceful) / `Close` (cancel) on the host and `Cancel` on one agent. The MECHANISM is real and go-test-witnessed; the status tag above stays simulated-not-shipped because the acceptance runs against the **Mock engine** (no live engine on the build box), the host sits behind an explicit import boundary (gen/second-next architectural OPTION — nothing in the default `fak serve`/`fak guard`/dispatch path constructs a `Host`), and the density / $-per-task win the design targets is **NOT yet measured** against a live engine or the production spawn path. Witness: `.\test.ps1 -run TestHostSmoke100AgentsOneGatewayOneAuditSink ./internal/microagent/` — 120 microagents run to completion in ONE process, the shared planner + the one gateway each carry exactly `agents·turns` requests, one session-table entry per agent (all `Stopped`/"done"), and one audit sink sees every spawn+done. Promotion: point the dispatch path at the host instead of detached CLIs (#2030) and confirm per-agent process weight was the binding cost (#2033). Demotion/retirement: retire the host if #2033 shows per-agent cost is dominated by provider seats/rate limits (host buys no density) or the isolation floor demands per-agent OS processes anyway (#2018). Invalidating assumption: `Step` assumes an agent loop can be driven as a resumable in-process step over a shared planner seam — the #2001 RunArm per-turn extraction is still open, and if the real loop needs per-agent OS state (cwd, credential files, process-tree tools) the goroutine model under-isolates and the host must grow a subprocess `ToolExec` seam (#2003/#2014) first. See the closing-evidence block in `internal/microagent/doc.go`.
