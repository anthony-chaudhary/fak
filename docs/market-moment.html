01

Where the market is today

Coding agents are no longer a demo layer. They are a daily driver: harnesses run inside terminals and IDEs, file real PRs, and increasingly run unattended on recurring repo work. The industry conversation has moved with them — from benchmarking models on code generation to governing what agents are allowed to do (the existence of an OWASP Agentic Top-10 and an MCP Top-10 is the symptom: a risk list is published only for a practice that is already widespread).

The unit of software work is shifting with it. The old unit was "a developer writes a change and files a PR, peers review it." The new unit is "agents produce most of the change; humans direct, review, and own the decisions that matter." Nobody has to believe the end state for the trend to matter — only that the direction is machine-paced change with human checkpoints.

02

The bottleneck migrates downstream

Walk the loop and watch where the time goes.

the old loop

think → write → test → PR → review

Days per cycle. The human wrote the code, so review load scaled with writing load — one human, one reviewer, roughly matched.

the agent loop

generation compresses to minutes

An agent drafts, tests, and re-works a change while you read its first summary. A fleet of agents runs many such cycles in parallel lanes at once.

Nothing in that compression makes the human checkpoints faster. Review throughput, acceptance testing, and trust decisions stay human-paced while generation becomes machine-paced. The queue does not disappear — it moves. A fleet that can produce fifty changes a day behind a review gate that absorbs five is a five-change-a-day fleet. The speedup is real and it is thrown away at exactly one step.
03

The two answers the market offers — and why both fail at fleet scale

answer 1 · safe, but serial

Gate everything by hand

A human reviews every PR, approves every tool call, verifies every "done." This is the world most teams live in, and it rebuilds the old bottleneck one step downstream: review load now scales with agent output instead of human output. It is safe, it does not scale, and it cancels the very speed the agent was bought for.

answer 2 · fast, but forgeable

Just trust the AI

Auto-accept the tool calls, auto-merge the PRs, read the agent's summary as ground truth. This removes the human queue — and removes the safety net at the same time. And it fails in a way that is worse than slow: unauditable. When the agent grades its own homework, neither the human nor the next agent can tell which parts of the story were checked.

the bolt-on middle that isn't one

After-the-fact audit

Observability platforms record what the agent did and alert afterward — useful, but they observe the loop without governing it. A log entry does not stop the bad tool call; it files the report. Prevention and audit are different layers, and the market mostly sells the second.

What is missing is the layer between: a runtime that governs the boundary while the agent runs — fast enough not to become the new human queue, and defined enough not to be a leap of faith.
04

The middle ground fak builds: trust as a definition, not a leap

The binary framing treats trust as a switch. It is actually a dial, and the design space between the extremes is where fleets become usable. Each mechanism moves one class of decision off both extremes and onto the kernel.

the binary
the middle path fak implements
Human runs every tool ↔ model calls anything
A default-deny capability floor. You enumerate what the agent may do; everything else refuses by structure, without a recognizer that can fail open. (why default-deny beats a classifier)
Human verifies every done-claim ↔ believe the agent's summary
The kernel re-checks the claim against evidence. A done-claim is graded against git — the subject is forgeable, the diff is not. (verify, don't trust)
Human coordinates who touches what ↔ hope parallel agents don't collide
Lane leases and arbitration. The kernel decides whether two agents may run at once on the same files, and refuses with a structured reason a peer can act on. (lane leases, lane arbiter)
Human approves every exception forever ↔ silent override
Graduated exceptions. An attending operator can approve one exact refused call — the agent cannot approve itself (operator approval); blocked gates have recorded, expiring, scope-bound waiver paths instead of a permanent lock or a silent bypass.
Human triages every failure ↔ agent retries blindly
Structured refusals from a closed vocabulary — a machine-checkable reason token, not free-text "I couldn't do it." (verify, don't trust)
Trust the model's word about what ran ↔ read raw logs yourself
The verdict fold at the boundary. Proposed call → verdict → only an allowed call executes; suspicious results are quarantined. (the tool call is a syscall)

The pattern in every row: the human keeps the decision (what is allowed, what a gate means, whether this exception is worth its risk) and stops being the serialization point (approving each instance, coordinating each pair of agents, reading each log). Policy moves into the kernel; judgment stays with the person.

That is the middle ground — not "trust the AI," not "do it as a human," but define what you trust, and make the runtime prove the rest.

The sentence to keep: the model proposes, the kernel disposes — and the kernel checks.

05

Born from real problems, not from a thesis

None of the mechanisms above were designed forward from a vision of autonomous agents. Each is the scar of a specific failure observed running agent work for real, day after day.

The honest claim, and a stronger one than a prediction: fak is not a forecast about what agents will need — it is the recorded list of what broke when agents ran for real. The roadmap is downstream of the scars, not ahead of them.
06

The serving side of the same story

Fleets change what inference has to do, not just how much of it. A fleet's serving layer must batch concurrent lanes into one decode, reuse the prefixes that multi-turn tool loops share, fail over when a provider pauses, let the operator's interactive turn preempt background batch work, and meter against budgets — or the coordination layer above it starves.

fak's serving runtime exists because those are the observed failure modes of agent serving, not speculative ones; see the capability floor and the honest boundary for what is measured today versus what is not. Running the loop on your own machine keeps it fast and keeps the code local — the same trust argument applied to data.

07

What this frame is not

The part to read before citing the pitch.

not "fully autonomous"

The durable guarantee is the enforcement layer, not the model's judgment; the human keeps review responsibility for the decisions that matter. fak moves work off the human's desk; it does not remove the human.

not "review is dead"

Review changes shape: from reading every change to defining what the runtime must prove about every change, then sampling the residue with evidence in hand.

not "every layer is finished"

What is measured, limited, or planned is tracked in CLAIMS and the status page; the motivation frame does not upgrade any claim tier.
